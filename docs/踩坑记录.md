# 踩坑记录

开发 `find_word` 过程中遇到并解决的问题，以及从中沉淀出的经验。
本文同时是一份调试思路的参考：一个"看着莫名其妙"的 bug，是如何一步步从怀疑走到定位根因的。

---

## Bug：函数内移动局部指针，调用方缓冲区却是空的

### 现象

在 `Findwords` 中匹配到单词后，函数内部用指针跳过释义前的空格，在函数里 `printf` 能正确打印出释义；
但函数返回 `main` 后，打印 `out` 却是**空字符串**。

### 复现

- `dict.txt` 每行格式为「单词 释义」，中间用空格分隔；
- `main` 中定义 `char out[512] = {0};`，调用 `Findwords(words, out)`；
- `Findwords` 中匹配成功后执行：

```c
pout = buffer_line + strlen(pwords) + 1;   // 指向释义
for (; *pout == ' '; pout++);              // 跳过释义前的空格
printf("%s\n", pout);                      // 函数内能正确打印
break;
```

- 回到 `main` 打印 `out`，结果为空。

### 调试过程

最初怀疑是 `for` 循环把指针移到了字符串末尾（`\0`）上，于是加调试打印观察指针指向：

```c
printf("[DEBUG] *pout = %d (%c)\n", *pout, *pout);
```

- 循环前：`*pout = 32 ( )` —— 空格
- 循环后：`*pout = 110 (n)` —— 字母 n

说明 `for` 循环完全正常，`pout` 成功跳过了空格。既然指针指向没问题，问题就一定出在别处——于是定位到了根因。

### 根本原因

C 语言函数参数是**按值传递**的。调用 `Findwords(words, out)` 时，只是把 `out` 的地址**拷贝**了一份给 `pout`。
函数内部对 `pout` 执行 `pout = ...` 或 `pout++`，改变的只是**这个拷贝**的指向；
`main` 里的 `out` 数组从头到尾没被写入过，依然是初始化时的全 `{0}`。

> 一句话：**在函数里移动指针 ≠ 修改调用方的数组内容。**

### 解决方案

跳过空格后，用 `strcpy` 把释义真正拷贝进 `pout` 指向的那块内存：

```c
if (0 == strcmp(pwords, strtok(buffer_line, " ")))
{
    char *p = buffer_line + strlen(pwords) + 1;
    for (; *p == ' '; p++);
    strcpy(pout, p);      // 把释义拷贝到 main 的 out 数组
    return 0;
}
```

`pout` 虽然是局部指针，但它和 `main` 的 `out` 指向同一块内存；用 `strcpy` 往这块内存写数据，`main` 自然就拿到了释义。

### 经验总结

| 需求 | 做法 |
|------|------|
| 修改外部数组的**内容** | 传一级指针 `char *`，函数内用 `strcpy` / `memcpy` 写入 |
| 修改外部指针的**指向** | 传二级指针 `char **`，函数内用 `*p = ...` |
| 只**读**外部数据 | 传一级指针并加 `const`，如 `const char *` |
